# 售后 CSV 与当前平台需求完整对照

更新日期：2026-09-08

> 本文保留 0.4.0 当时的字段盘点证据。问题规则、数据源和生产验收结论已由 0.6.1 更新；当前分类与剔除口径以[0.6.1 五大分类规则灰度、对账与发布记录](../operations/五大分类规则灰度对账_20260915.md)为准。

## 1. 对照结论

本次按“原始 CSV → 当前 0.4.0 代码 → 当前生产运行”三层核验，结论如下：

| 结论项 | 结论 |
| --- | --- |
| CSV 能否单独支撑当前完整看板 | 不能 |
| CSV 能支撑的当前核心数据 | 售后问题分子、付款周期、商品标题、售后商品 ID、一级/二级/三级问题，以及用于仓库关联的订单号、运单号 |
| 当前看板仍必须依赖的数据 | 商家编码、全店/商家编码/商品/仓库订单数与销量、问题规则、仓库映射、同步批次与数据水位 |
| `店铺名称`是否属于当前看板必需字段 | 否。CSV 有该字段，但当前 0.4.0 页面没有店铺筛选、店铺汇总或店铺权限 |
| 处理方式、退款、物流分析是否已经上线 | 否。CSV 中有部分数据，但当前页面、指标和 Excel 没有这些分析能力 |
| 商品标题是否可以作为商品主键 | 不可以。标题存在一对多和多对一，只能用于展示与搜索 |
| 当前文档与本地 0.4.0 需求是否已逐项对齐 | 是，已按当前代码、README、CHANGELOG 和现有产品文档逐项对照 |
| 是否已完成生产数据和线上页面验收 | 否，待确认。公司 Mac mini 的 Tailscale、局域网和 Bonjour 三条 SSH 路径当前均未建立握手；公网入口只能确认跳转员工登录，无法读取登录后的真实页面和数据库 |

因此，本文件可以作为当前 0.4.0 的字段需求清单，但不能据此声称“生产数据已经完全满足需求”。生产验收项见第 11 节。

## 4. 当前 0.4.0 产品需求逐项对照

### 4.1 页面和指标

| 当前能力 | 当前真实口径或字段 | CSV 能否单独满足 | 缺口或说明 |
| --- | --- | --- | --- |
| 全量售后问题 | 当前周期内全部售后问题行 | 基本可以 | 需要按稳定业务键去重；CSV 的 `id` 单列不唯一 |
| 经营异常问题 | 售后问题命中启用规则，且 `include_business_exception=1` | 不可以 | CSV 有三级问题路径，但没有管理员维护的问题规则 |
| 产品销量 | 全部已完成订单的 `sales_qty` | 不可以 | `购买数`只是发生售后的记录内购买数，不能代表同期全部销量 |
| 销售订单 | 全部订单去重数 `order_count` | 不可以 | CSV 只包含发生售后的记录 |
| 经营异常售后率 | 经营异常问题数 ÷ 同粒度销售订单数 | 不可以 | 缺订单分母与问题规则 |
| 售后率周环比 | `(当期售后率 - 上期售后率) ÷ 上期售后率` | 不可以 | 缺连续周期的全部订单分母 |
| 较上期变化 | 当期售后率减上期售后率，单位为百分点 | 不可以 | 缺订单分母 |
| 预计问题数 | 上期售后率 × 当期订单数 | 不可以 | 缺订单分母 |
| 超出预期问题数 | 当期问题数减预计问题数 | 不可以 | 缺订单分母 |
| 预警状态 | 重点预警、正在上升、正在改善、保持稳定 | 不可以 | 同时依赖售后率、变化百分点、超预期问题数和阈值 |
| 近 5 个完整周 | 周日至周六，读取 5 个已完整结束的周 | 部分可以 | CSV 可提供付款时间和售后分子，仍缺完整周订单/销量分母 |
| 本周同进度 | 本周与上周相同已结束自然日，并用任务创建时间限制观察进度 | 部分可以 | `付款时间`缺 2 行，`创建时间`完整；仍缺每日订单/销量分母和共同水位 |
| 产品预警榜 | 按商家编码归并，保留商品链接下钻 | 不可以 | CSV 没有商家编码 |
| 仓库风险 | 只统计一级问题为“库房问题”且进入经营异常的记录，分母为映射后仓库订单 | 不可以 | `[WDT]仓库编号`仅 33 行有值；还缺仓库映射、规则和仓库订单分母 |

### 5.2 外部订单与销量汇总

这些数据不应补进每一行售后 CSV，而应继续由订单数据生成日、周汇总。

| 粒度 `grain_type` | 键 `grain_key` | 当前来源 | 必需值 |
| --- | --- | --- | --- |
| `total` | `__all__` | WDT 已发货订单 | 日期/周区间、去重订单数、销售件数 |
| `merchant_code` | 商家编码 | WDT 已发货商品行 | 日期/周区间、去重订单数、销售件数 |
| `aftersales_product_id` | 已确认商品 ID | 抖店已完成订单明细 | 日期/周区间、去重订单数、销售件数 |
| `warehouse` | WDT 仓库名称 | WDT 已发货订单 | 日期/周区间、去重订单数、销售件数 |

日汇总表为 `dws_crm_order_daily`，周汇总表为 `dws_crm_order_weekly`。商品分母未覆盖时，只有“一个商家编码明确对应一个商品 ID”的记录允许使用商家分母安全回填；一对多不得推断，页面必须显示“—”，Excel 留空。

## 6. 商品标题与商品名称的影响

CSV 的 `商品标题`可供当前页面显示为“商品名称”，但不能参与唯一识别或替代商家编码、商品 ID。

本文件实际关系如下：

| 检查项 | 结果 |
| --- | --- |
| 有效商品 ID | 144 个 |
| 有效商品标题 | 157 个 |
| 对应多个标题的商品 ID | 52 个 |
| 落在这些多标题商品 ID 下的记录 | 3,375 行，占 95.5% |
| 同一个标题对应多个商品 ID | 29 个标题 |
| 单个商品 ID 最多对应标题数 | 4 个 |

影响边界：

- 会影响页面展示名称和按名称搜索的命中结果。
- 不应影响售后问题数、订单数、销量、售后率和预警，只要这些指标始终按任务行、商家编码和商品 ID 计算。
- 当前代码先在同一“商家编码 + 商品 ID + 问题路径”内取一个标题，再在产品汇总中偏向较长标题，因此展示名称可能不是业务人员期望的标准名称。
- 如需统一产品名称，应补充权威的商品 ID/商家编码到标准产品名称映射；在此之前只把 CSV 标题当展示快照，不把它改名为“标准产品名称”。

## 10. 与当前平台一致的边界说明

以下说法与当前 0.4.0 一致：

- 当前产品是经营分析和预警看板，不是单工单处理系统。
- 售后问题数是按班牛任务的子商品行形成的事实行，不等同于去重订单数，也不等同于任务数。
- 售后率分母是同期全部订单数，不是售后 CSV 中的 `购买数`。
- 产品页按商家编码归并，再下钻到售后商品 ID 和问题路径。
- “售后商品ID（班牛）”与“抖店商品ID（已确认）”必须分开表达；CSV 的 `商品ID`不能自动同时承担两种身份。
- 商品标题只用于展示和搜索，不能替代商家编码或商品 ID。
- 未命中启用规则的问题进入“待分类”，不进入经营异常；剔除项仍保留在全量问题中。
- “进入趋势”和“进入飞书通知”当前只完成配置保存；不能把它们写成已完整生效的筛选或通知能力。
- 仓库页只统计一级问题为“库房问题”且进入经营异常的记录。
- 分母缺失时售后率必须留空；商品一对多不得使用商家分母推断。
- 当前页面没有店铺、处理方式、退款、金额、物流公司、人员和 SLA 分析。

## 12. 最终判定

这份 CSV 对当前看板来说是“售后事实来源的一部分”，不是完整的数据集。

它已经覆盖当前售后分子分析所需的大部分字段，但至少缺少商家编码，并且无法提供订单/销量分母、问题规则、仓库映射和数据水位。商品标题存在明显的一对多和多对一，只能作为显示名称。CSV 中其余处理、退款、金额、物流公司、人员和时效字段不得被写成当前已上线能力；它们只能作为有事实基础的后续需求候选，且仍需业务确认。
