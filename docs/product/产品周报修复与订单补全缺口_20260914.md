# 产品周报修复与订单补全缺口

## 已实施口径

- 产品周报按班牛售后 `api_created_at` 归入周日至周六的完整周。
- 只统计规则中启用且进入经营异常的售后商品记录。
- 默认选择上一个完整周，可选择最近五个完整周。
- 产品以完整商家编码为一行，不按商品名称、基础编码或装数合并。
- 只展示所选周问题数大于零的产品，按问题数降序；并列按商家编码稳定排序。
- 缺商家编码的记录单列为“待匹配”，计入周问题总量，不参加产品排名。

页面、分页接口、创建周下钻和 Excel 共享 `basis=created` 与 `week_start`。原经营总览和仓库分析继续使用既有付款周口径。

## 采集与补数

班牛同步窗口按售后创建时间或修改时间判断，不再因订单付款时间较早而漏掉新售后。每次同步先拉完并核对固定分页快照，再计算新增、变化、未变化及缺创建时间数量。`--dry-run` 只输出差异；正式执行将整个批次置于同一事务，失败回滚。

首次历史核对范围为 2026-08-02（含）至 2026-09-13（不含），覆盖产品周报五个展示周及前一比较周。

生产预演完整读取 63,729 个班牛任务、638 页，范围内生成 15,352 条商品记录：新增 1,895 条、更新 3,768 条、未变 9,689 条、缺创建时间 0 条。正式补数使用相同冻结范围并在单一事务中写入，结果与预演一致，业务键重复数为 0。

补数后 2026-09-06 至 2026-09-12 共 386 条经营异常记录，其中有商家编码 308 条、待匹配 78 条，对应 162 个有量产品。页面排名、产品下钻和产品 Excel 已按这组数字对账通过。

## 子订单自动补全边界

最初仅核对旺店通 API 增量表时，近五周 146 条缺商家编码记录均未命中。进一步核对旺店通历史销售出库明细 `ods_wdt_stock_out` 后，确认该表可通过店铺、主订单号和子订单号补全一部分记录。

日常班牛同步后自动执行旺店通补全。优先使用店铺、主订单号和子订单号；该子订单只有一个非空商家编码时才写入。旺店通没有对应子订单时，仅在整个店铺订单只有一个非空商家编码时回退补全。多候选和未找到记录继续保留待匹配状态，商品标题及组合装候选编码不用于猜填。

2026-08-02 至 2026-09-13 的生产补全共处理 1,844 条缺编码记录，其中 918 条唯一补齐：772 条按子订单唯一命中，146 条按整个订单唯一命中。其余 343 条子订单存在多个编码、519 条订单存在多个编码、64 条无可用旺店通记录，继续待匹配。补全后 2026-09-06 至 2026-09-12 的经营异常总量仍为 386 条，已匹配 349 条、待匹配 37 条、对应 183 个有量产品；两类已写入记录独立复核错误数均为 0。
