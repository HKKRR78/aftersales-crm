## 同版本发布门槛

- `package.json` 和用户可见版本保持 0.6.1，不创建另一个版本号。
- 构建 ID 根据候选源码哈希生成，并通过 `X-Build-ID` 响应头传递；数据接口和导出另带 `X-Data-Batch`。
- 本地 `pnpm verify` 通过仅证明静态检查、隔离测试及构建，不能替代真实数据验收。
- 新端口候选应固定 `CRM_REPORT_BATCH_ID`，经真实员工入口验证所有页面、筛选、下钻、分页和 Excel；不得用身份头直连检查代替员工入口验收。

- 完成来源稳定性、店铺有效期、付款窗口覆盖和旧工单消失核对后，再停旧任务、切换 Web 与新任务，防止两个写入任务并行。

## 回滚和审计

本轮完整回滚演练尚未执行。不得仅切回 Web 链接就宣称回滚完成。回滚记录必须同时包含应用、数据任务、报告批次及规则；历史原始记录和证据文件不得清除。

`crm_report_publish.py select` 用于正常发布，会拒绝源数据或规则已过时的批次，**不能作为任意历史批次强制回滚命令**。在实际候选切换前仍需完成应用、任务、批次和规则一致的回滚演练，并记录确切操作及验证结果。不可用关闭核验门槛实现回滚。

进程、MySQL 和新鲜度检查只是验收的一部分。服务器上的真实状态应以 LaunchAgent 参数、运行进程、当前链接、响应头及实际业务数据共同判定。
