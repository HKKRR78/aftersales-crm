# 新版售后面板重构说明

## 目标

第一阶段只替换旧 Python Web 面板，建立可长期扩展的售后经营分析服务。班牛采集、订单聚合和 MySQL 数据不在本阶段迁移。

## 技术基线

| 层级 | 选择 |
| --- | --- |
| Web | Next.js 16.3.1 App Router |
| UI | React 19.2 + 服务端组件 |
| 语言 | TypeScript 5.9 |
| 数据库 | MySQL 8，只读 `ecom_profit` |
| 数据库客户端 | `mysql2/promise` 连接池 |
| 身份 | 公司网关注入员工身份头 |
| 部署 | standalone + launchd + 公司网关 |
| 测试 | Vitest、TypeScript、ESLint、生产构建 |
| 大表格 | TanStack Virtual，只挂载可见行 |

## 已实现页面

- 经营总览
- 完整周趋势与本周同进度切换
- 问题类别风险排行
- 商品预警与精确下钻
- 问题明细筛选和虚拟滚动
- 仓库风险排行
- 数据更新时间与滞后状态
- Web 健康检查与数据就绪检查
- 桌面、平板、手机三档响应式布局

## 本地验收模式

开发环境可通过 `AFTERSALES_DEV_DATA=fixture pnpm dev` 生成 2,400 条问题组合、800 个商品和 18 个仓库。该数据只用于本地交互与性能验收，生产构建和生产运行不会启用。

已完成的本地浏览器验收包括：

- 总览、问题明细、商品和仓库四个页面正常打开。
- 2,400 行问题明细首屏只挂载可见行，深度滚动时保持有限 DOM 行数。
- 商家编码筛选写入 URL，刷新后仍可复现筛选结果。
- 1280、834、390 像素宽度下无页面横向溢出。
- 平板和手机端明细以卡片行展示，保留商品、问题、预警、问题数、售后率和变化值。
- 浏览器控制台无错误或警告。

## 数据安全规则

- 不在页面请求中回扫订单明细大表。
- 不使用 HTML、WPS 或 JSON 快照兜底。
- 日/周订单聚合缺失时明确报错，不把零值或旧数据展示为正常。
- 数据更新时间超过默认 16 小时时，`readyz` 返回 `503`。
- 页面只接受公司网关注入的 `admin`、`viewer` 身份。
