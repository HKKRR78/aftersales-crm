# 售后统一数据源迁移

## 运行模型

新工单接口写入 `ods_crm_ticket_raw` 和 `ods_crm_aftersales`。班牛历史通过一次性导入进入同一事实表，并以 `source_system=banniu` 保留来源。看板、规则发现、旺店通补全及仓库映射只读取统一事实表。

`etl_crm_ticket_batches` 是新工单数据水位的唯一依据。只有完整分段双读一致、来源记录无消失且事务提交成功的批次标记为 `published`。失败批次保留错误摘要，但不会推进页面水位。

## 首次预演

1. 在隔离验收库执行 `python3 scripts/crm_schema.py`。
2. 执行 `python3 scripts/crm_banniu_history_import.py --dry-run` 核对历史行数，再去掉 `--dry-run` 导入。
3. 注入 `TICKET_EXPORT_API_JWT`，使用明确日期运行 `crm_ticket_sync.py --start-date YYYY-MM-DD --end-date YYYY-MM-DD --dry-run`。
4. 使用 `crm_cutover_reconcile.py` 输出来源汇总和疑似重复项；疑似记录只供人工判断，不自动合并。
5. 正式同步后核对页面、下钻和 Excel，再使用 `--approve-batch` 和 `--approved-by` 批准批次并启用新工单统计。

批准前，新工单事实只参与对账，不进入正式看板；班牛历史继续提供原有统计。来源启用后，后续成功批次自动继承已批准状态。

## 停止条件

以下任一情况均停止切换：双读摘要不同、分页出现重复身份、已覆盖记录从接口消失、交接范围未确认、疑似重复未处理、班牛未结工单归属不明、字段全量覆盖率未通过或登录后的看板与 Excel 对账不一致。

生产切换时使用新的 launchd 标签和日更入口。旧班牛采集入口已经从现役源码移除；回滚应恢复匹配版本的应用、数据库备份和旧调度配置，不在新代码中添加运行时回退。
