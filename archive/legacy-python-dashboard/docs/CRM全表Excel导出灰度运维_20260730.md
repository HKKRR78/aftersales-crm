# CRM 全表 Excel 导出灰度运维

## 当前架构

- 对外地址：`http://192.168.3.135:8088/crm`
- Nginx：监听 `0.0.0.0:8088`
- 稳定后端：`127.0.0.1:18088`
- 候选后端：`127.0.0.1:18089`
- 稳定版当前设置 `CRM_XLSX_EXPORT_ENABLED=0`
- 候选版当前设置 `CRM_XLSX_EXPORT_ENABLED=1`
- 两个 Python 后端只监听回环地址，共用用户与会话目录

当前灰度阶段默认请求进入 18088。带 `crm_canary=1` Cookie 的请求进入 18089。

## 灰度链接

- 开启灰度：`http://192.168.3.135:8088/crm/canary/enable`
- 关闭灰度：`http://192.168.3.135:8088/crm/canary/disable`

灰度 Cookie 有效期 1 天，作用域为 `/crm`。开启或关闭后都会跳回 CRM 首页。

## 验收范围

已登录的 viewer、exporter、admin 可以在候选版看到：

- Dashboard：一级类别汇总、重点问题明细、仓库概览，共 3 个 Excel 按钮。
- 售后明细、仓库问题视图、商品问题视图，各 1 个 Excel 按钮。

内网免登录访客不显示按钮，直接访问 Excel 接口返回 403。管理员用户列表没有导出按钮。旧 CSV 接口继续按照原 exporter/admin 权限工作。

Excel 接口：

```text
GET /crm/export?view=<category|detail|warehouse|products>&format=xlsx
```

支持 `q`、`p1`、`p2`、`rise` 页面筛选参数，导出全部筛选结果，不受页面 30/500 条限制。

## 一个工作日后的正式切换

满足以下条件后再正式切换：

- 无 5xx、Traceback 或持续超时。
- 4 类 Excel 均能打开。
- 筛选后 Excel 行数与完整筛选结果一致。
- viewer、exporter、admin 均能导出，内网免登录访客仍为 403。

先把全量流量导向已验证候选：

```bash
cp /Users/Shared/ecom-profit/projects/crm/deploy/nginx/upstream-map.full-canary.conf \
  /Users/Shared/ecom-profit/projects/crm/deploy/nginx/upstream-map.conf
/opt/homebrew/opt/nginx/bin/nginx -t \
  -c /Users/Shared/ecom-profit/projects/crm/deploy/nginx/nginx.conf
/opt/homebrew/opt/nginx/bin/nginx -s reload \
  -c /Users/Shared/ecom-profit/projects/crm/deploy/nginx/nginx.conf
```

然后将稳定版 plist 的 `CRM_XLSX_EXPORT_ENABLED` 改为 `1`，重新加载 `com.ecom-profit.crm-dashboard`，直连 `127.0.0.1:18088` 验收 4 类 Excel。

验收通过后恢复 18088 为默认：

```bash
cp /Users/Shared/ecom-profit/projects/crm/deploy/nginx/upstream-map.stable.conf \
  /Users/Shared/ecom-profit/projects/crm/deploy/nginx/upstream-map.conf
/opt/homebrew/opt/nginx/bin/nginx -t \
  -c /Users/Shared/ecom-profit/projects/crm/deploy/nginx/nginx.conf
/opt/homebrew/opt/nginx/bin/nginx -s reload \
  -c /Users/Shared/ecom-profit/projects/crm/deploy/nginx/nginx.conf
```

## 回滚

本次部署备份：

```text
/Users/Shared/ecom-profit/backups/crm_excel_export_20260730_123927
```

灰度问题只需使用关闭灰度链接；默认稳定流量不受影响。

如需完全回滚，先停止 Nginx和两个新后端，再恢复备份中的生产代码、原 Dashboard plist，并重新加载原 `com.ecom-profit.crm-dashboard`。回滚完成后确认 Python 再次监听原 8088。
