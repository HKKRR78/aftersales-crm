## 已确认风险

### 高：外部认证边界可被伪造的 `X-Forwarded-For` 影响

`crm_server.py` 无条件信任客户端传入的 `X-Forwarded-For`，并据此判断是否为内网访客。测试确认该请求头可以直接改变登录判断。若 Tailscale/反向代理入口恢复可用，客户端可伪造私网地址绕过登录，获得内网访客只读权限。

建议只在请求确实来自受信任反向代理时读取该请求头；直接连接时只使用 socket 对端地址。

### 高：运行态用户与会话文件权限过宽

- `users.json`：`0644`
- `sessions.json`：`0644`
- `initial_admin_password.txt`：`0600`

前两个文件可被服务器其他本地账户读取，分别包含密码哈希和有效会话令牌。建议统一改为 `0600`，并让 `write_json()` 在每次原子替换后主动保持权限。

### 高：班牛同步触达分页硬上限

原日更记录为 `tasks_seen=12000`，正好等于 `120 pages × 100 rows`。脚本不是因为空页或连续旧页而停止，存在近 8 周数据被分页上限截断的可能。

2026-08-10 已修复：移除固定 `max-pages`，使用 API 的 `total` / `total_page_num` 完整分页，并以第一页最大任务 ID 固定本轮快照；快照任务数不完整时明确失败。

### 中：管理员拒绝路径返回空响应

内网访客访问 `/crm/admin/users` 时，代码使用中文 HTTP reason phrase 调用 `send_error()`，Python 标准库按 Latin-1 编码响应行并抛出 `UnicodeEncodeError`。实测客户端未收到有效 HTTP 状态，错误日志新增一次对应异常。

导出拒绝路径已经改为普通 HTML `403`，管理员拒绝路径应使用同样处理方式。

### 中：Tailscale 应用入口当前不可用

- `100.99.61.3:22` TCP 可建立，但 SSH 在 banner exchange 阶段超时。
- `100.99.61.3:8088` TCP 可建立，但 HTTP 请求超时。
- LAN 与 Bonjour 路由正常，当前运维连接使用 LAN `192.168.3.135`。

现象更像 Tailscale/VPN/代理路由层拦截，而不是 CRM 进程故障。按服务器连接规范，未擅自修改 VPN、代理、防火墙或 Tailscale 设置。

### 中：订单周汇总残留旧周边界数据

`dws_crm_order_weekly` 同时存在两组交错周窗口：

- 旧数据：周六起、下一周六为排他结束日期；
- 当前数据：周日起、下一周日为排他结束日期。

页面按精确日期键读取当前周日口径，暂未被旧数据污染；但文档中的 `20,964` 总行数包含旧数据，且表会保留无效历史窗口。清理前需确认精确日期范围与预计删除行数。

生产 CRM 目录不是 Git 工作树，也没有在服务器其他 Git 仓库中找到对应源码。当前本地已拉取代码基线，但尚未创建基线提交。任何生产改动前都应先形成可回滚版本。

另外，项目没有依赖清单和自动化测试；当前只能通过系统 Python 环境、语法检查、HTTP 冒烟和数据库只读核验确认。
